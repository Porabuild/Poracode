## 1. Verdict on V5

V5 delivered most of what it set out to do, and the parts that landed are well built:

- One host composition (`composeHostServices`) called by desktop and standalone; `desktopAppReady`
  split to 223 lines, nothing over 200 lines in `desktopApp*.ts`.
- Automatic, journaled, resumable data-root promotion with both crash windows tested.
- One `SupervisorEvent` reducer with injected recovery; per-consumer engines; `clientRuntime` the
  sole `window.poracode*` reader, lint-enforced; versioned IPC map and engine protocol.
- Contract registry drives `httpRouter` (195 lines, was 1 345); manifest generated; scopes enforced
  centrally per route. Remote WS overflow/gap resync is real and tested.
- Loopback default, TLS material, rotating tokens with revocation, image hardening, port-forward
  tickets, Host-header gate, audit log, relay channel binding, `SECURITY.md`.
- Generated pairing, terminal-cursor, and key-encoding machines with a CI byte-compare gate.
- Native CI (`ios_ui` on PRs, blocking `native_gate`), SIGTERM drain, config file, log rotation.

Against the plan's own acceptance column the score is lower than the execution log records:

The §3 target architecture is **not reached** on the client side: there is no `HostTransport`
interface, preload IPC is a permanent full data plane rather than a bootstrap path, and eight
version constants sit on the renderer→host path. The trust surface has one Critical hole: TLS
certificate pinning is inert in every shipping client, so the `lan`/`tailnet` TLS story does not
yet protect first pairing.

Execution-log corrections (V5 §6): "2.5 is now COMPLETE" overstates (see T-1 below); the
"39 vectors" for the pairing spec executor is the pre-existing `pairing-url-cases.json` fixture,
unchanged across the range (the pairing machine has a self-consistency validator plus 29 `it()`
cases); "viewer denied on 24 / admitted on 20" was point-in-time (now 40 / 18, and the test asserts
only `>20` / `>15`); 4.9 is recorded as delivered while its acceptance (out-of-checkout install
qualification in CI) is unmet.

- **A.1–A.4 gate any public `lan`/`tailnet` TLS release**; ship first. A.5–A.10 are cheap and independent.

## 7. Finalization review (2026-09-20)

This pass reviewed the uncommitted V5/V6 tree against `2f780b86b` after reading
both implementation and verification handoffs. It supersedes the earlier
claim that no acceptance-affecting defects remained. Independent review
covered trust, transport and simplification; the parent covered packaging,
upgrade lifecycle, compatibility evidence and final verification. Generated
models, broad native UI and mechanically moved host code received reduced-depth
review; this is not a claim of exhaustive manual inspection of every line.

Validated fixes:

- Electron pinning now binds to the certificate on the actual HTTPS request,
  before releasing credentials. The version-3 HTTP bridge carries the pin,
  refuses redirects and preserves certificate-mismatch errors. Electron's
  certificate gate evaluates the exact WebSocket origin without allowing a
  cached earlier certificate acceptance to bypass a newly registered pin.
  Fingerprint-less re-pairing clears stale pins on Electron and Android.
- Managed loopback requests refresh expired credentials, including concurrent
  requests and delayed 401 responses. Server session retention follows the
  refresh lifetime while expired bearer tokens and WebSocket tickets remain
  invalid. Secondary paired servers do not overwrite managed desktop
  capabilities; snapshot recovery and reconnect handle each sequence space.
- Upgrade exceptions after the swap restart the previous release. Automatic
  unmanaged restart authenticates the live owner; stale PID files cannot
  authorize signalling, and externally discovered processes are never escalated
  to SIGKILL. Rollback tracks the actual candidate child. Unverifiable owners
  require manual stopping. The built-in systemd service is only restarted for
  its `/opt/poracode` prefix.
- Promotion progress waits for its document and tolerates load/update failures.
  Its source-locale limitation remains unchanged.
- Initial installation and upgrade share the native-overlay implementation.
  The tarball includes the Dockerfile and overlay helper; the image installs
  runtime dependencies pinned to installed lockfile versions, applies staged bindings and owns its writable data
  directory. CI explicitly enables arm64 emulation and dereferences the pnpm
  package before copying it into the cross-build container. A container build
  and doctor check are now part of installation qualification.
- Native reducer emitters consume their declared rules/actions instead of
  repeating handwritten decisions. The background-task spec explicitly treats
  missing incoming tasks as a no-op (spec version 2; wire unchanged). Renderer
  reduction reuses the resulting identity rather than comparing tasks twice.
  The previously unregistered iOS follow-up queue test file is now in AppTests;
  its stale Swift syntax and explicit-null fixture representation were corrected.

Compatibility: HTTP bridge v3 rejects the previous frame version. Auth storage
retains its existing shape and tests cover old sessions without refresh fields.
Overlay v1/v2 inputs remain accepted by the shared helper. The new packaged
Docker/helper files are additive to install layout v1. Reducer specification
versioning is independent of the unchanged remote wire contract.

Remaining environment caveats: live SSH is still environment-gated; device
real-peer and Linux container qualification must pass their CI jobs. Android's
speculative pin on superseded pairing, pre-existing base translations and FIFO
pin-cache eviction remain the previously recorded follow-ups. No commits or
remote publication were performed by this pass.
